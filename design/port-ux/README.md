# Port menu studies

The Harbor hub was selected and implemented in the game. These pages preserve the comparison prototypes.

Open the [interactive comparison](http://localhost:5173/design/port-ux/index.html). A, B, and C switch layouts while preserving the sample voyage; Reset restores its starting state. The studies never load or save browser voyage data.

All game controls and information stay inside the 4:3 playfield, over the existing coastline and ship artwork. There are no external status panels. The controls above the frame select the prototype for comparison.

- **A: Direct commands.** A centered port directory, with services first and ship, cargo, journal, and voyage commands grouped below.
- **B: Harbor hub.** A bottom command window separates actions ashore from management aboard, keeping more of the port approach visible.
- **C: Tabbed logbook.** Port, Ships, Cargo, and Journal share a persistent set of tabs inside the menu window.

Ships contains vessels and crew. Cargo contains trade goods and provisions. Journal contains quests, expedition reports, and contacts. Voyage status gathers wind, speed, morale, and stores. The crew café shows vacant berths and recruitment cost, then explicitly shows when the fleet is fully crewed.

Provisioning, trade, recruitment, repairs, reporting contracts, and guild acceptance use the existing engine on an isolated sample voyage. Ship construction is a catalogue preview. Sailing is a still frame for layout comparison. No new gameplay systems are introduced.

The interaction checks cover supplies, trade feedback, recruiting into empty berths, ship lists, voyage information, and return navigation across all three layouts. Rendered previews were checked at 1280 pixels wide; each playfield retains a 4:3 aspect ratio.
